# PCT Build Plan

Source of truth: the PCT spec (69 sections + final requirements). This plan maps the spec's 14 implementation phases onto the repo and adds gating rules.

## Ground rules
- Benchmark engine comes before any UI. A pretty dashboard over fake results is a failure state.
- Each phase ends with its own tests passing before the next starts.
- Nothing is marked done unless it was run against a real proxy or a deliberately broken fixture.
- Anything not implemented is written as incomplete in docs, never mocked to look finished.

## Phases

| Phase | Name | Output | Exit gate |
|---|---|---|---|
| 1 | Architecture | packages skeleton, tsconfig, lint, CODEBASE_MAP | `tsc` clean on empty packages |
| 2 | Protocol and schema | result JSON schema, test definition types, manifest format, adapter interface | schema validation tests pass |
| 3 | Test server and fixtures | deterministic origins: GET, POST, redirects, cookies, compression, range, streaming, SSE, WS, CORS, CSP, SRI, large and malformed payloads | each endpoint has a contract test with curl |
| 4 | Browser runner | Playwright-driven Chromium, routing to proxy, per-test isolation, timeouts, cleanup | runner executes a dummy test and cleans up all workers, SWs, storage |
| 5 | Core tests | initial ~30 tests (Quick profile) | each test has a passing and a deliberately broken fixture case |
| 6 | Scoring engine | weighted scores, critical caps, partial weighting, skip exclusion | unit tests from spec section 64 pass without a browser |
| 7 | CLI | `pct run` with config, flags, JSON output, `--min-score` | CI exit codes verified |
| 8 | Fetcher analysis | signal extraction, profiles, inference | calibrated against real client samples (see OPEN_QUESTIONS Q3) |
| 9 | Adapter protocol | url-prefix, path-based, anonymous, declared-identity adapters | same test suite runs through each adapter |
| 10 | Web UI | Home, Run, Results, Compare, Tests, Transport, Docs | every view renders real JSON from a run |
| 11 | Results and comparison | result hashing, regression diff, shareable result pages | diff of two real runs matches hand calculation |
| 12 | Security hardening | SSRF boundary review, redaction, rate limits, threat model doc | red-team checklist complete |
| 13 | Documentation | methodology, test spec, scoring, adapter guide, CI guide | docs reference only things that exist |
| 14 | Full test suite | PCT tests itself | coverage on scoring and inference paths |

## Build order inside Phase 5 and 6
Quick profile first (about 30 tests). Scoring gets built against those 30, not against 200 hypothetical ones. This catches schema problems before they multiply.

## Definition of done
Spec section 68 plus the 12 final demonstrations (section 70). Each demo needs a saved artifact in docs/demos/ generated by the actual runner.

## Blocking decisions
See OPEN_QUESTIONS.md. Phase 9 and Phase 8 cannot start until their questions are answered.
